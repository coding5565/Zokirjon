# English Bot (Empower) — Telegram-бot для учителя английского языка

Telegram-бот для управления домашними заданиями по учебнику **Empower** (4 уровня ×
12 юнитов × 3 урока) и для проверки ученических работ **Writing/Speaking** с помощью
ИИ (OpenAI). Управление — через кнопочное меню (reply-keyboard), без слэш-команд.

> **Отклонение от исходного ТЗ**: изначально был указан google-genai/Gemini, но у
> заказчика был готов ключ только от OpenAI — по его решению провайдер заменён на
> OpenAI (`modules/ai_feedback.py`). Подробности — в разделе 9.

Учитель полностью управляет контентом (навигация Level→Unit→Lesson, добавление Д.З.).
Любой другой пользователь при первом `/start` сам указывает, кто он — ученик или
учитель — и получает соответствующий **полный** (учитель) или **урезанный**
(ученик: просмотр + Writing/Speaking) доступ только после того, как админ одобрит
его запрос прямо в Telegram (раздел 7).

## 1. Технологии

- Python 3.11+
- python-telegram-bot v22.x (асинхронный API)
- openai (официальный Python SDK OpenAI, `from openai import OpenAI`)
- sqlite3 (встроенный модуль)
- python-dotenv

## 2. Установка и запуск

```bash
cd english_bot
python -m venv .venv
# Windows:
.venv\Scripts\activate
# Linux/macOS:
source .venv/bin/activate

pip install -r requirements.txt
cp .env.example .env   # затем заполнить .env, см. ниже
python bot.py
```

При первом запуске бот автоматически создаст файл БД (`bot.db`) со всеми таблицами
и заранее засеет 144 пустых урока (4 уровня × 12 юнитов × 3 урока).

## 3. Заполнение `.env`

### 3.1 BOT_TOKEN
1. Откройте Telegram, найдите **@BotFather**.
2. Отправьте `/newbot` и следуйте инструкциям (укажите имя и username бота).
3. BotFather пришлёт токен вида `123456789:AAExxxxxxxxxxxxxxxxxxxxxxxxxxxxxxx` —
   вставьте его в `BOT_TOKEN`.

### 3.2 OPENAI_API_KEY
1. Перейдите на https://platform.openai.com/api-keys.
2. Войдите в аккаунт OpenAI и создайте новый ключ (Create new secret key).
3. Вставьте его в `OPENAI_API_KEY`. Ключ должен начинаться с `sk-...`, и на счету
   должен быть баланс/привязан способ оплаты — иначе запросы будут падать с
   ошибкой квоты (бот в этом случае покажет пользователю понятное сообщение об
   ошибке, см. ключ `error_ai_provider` в `locales.py`).

### 3.3 Свой Telegram ID (для TEACHER_IDS)
1. Откройте Telegram, найдите **@userinfobot**.
2. Отправьте ему любое сообщение — бот пришлёт в ответ ваш числовой ID.
3. Впишите его в `TEACHER_IDS` (через запятую, если учителей несколько:
   `TEACHER_IDS=111111111,222222222`).

### 3.4 Остальное
- `OPENAI_MODEL` — chat-модель для Writing и разбора Speaking-транскрипта (по
  умолчанию `gpt-4o-mini` — дешёвая и достаточно качественная для этой задачи,
  можно сменить без изменения кода).
- `OPENAI_TRANSCRIBE_MODEL` — модель распознавания речи (по умолчанию `whisper-1`).
- `DATABASE_PATH` — путь к файлу SQLite (по умолчанию `bot.db`).
- `MAX_MEDIA_SIZE_MB` — лимит размера аудио/видео для Speaking (по умолчанию 20 МБ).

## 4. Как выглядит выбор языка

Сразу после `/start` бот показывает inline-кнопки:

```
🌐 Выберите язык интерфейса / Tilni tanlang / Choose language:
[ 🇺🇿 O'zbekcha ]  [ 🇷🇺 Русский ]  [ 🇬🇧 English ]
```

Выбор сохраняется в БД (`users.language`) и используется во всех дальнейших
сообщениях этому пользователю: меню, кнопки, подсказки, ошибки, фидбек по
Writing/Speaking. Изменить язык повторно в этой версии нельзя — он запрашивается
только один раз, при первом `/start`.

После выбора языка учитель видит главное меню (2 столбца):

```
Beginner          Elementary
Pre-Intermediate  Intermediate
Writing           Speaking
```

## 5. Как добавить домашнее задание к уроку

1. В главном меню выберите уровень (например, **Beginner**).
2. Выберите юнит: **Unit 1** … **Unit 12**.
3. Выберите урок: **Lesson 1** / **Lesson 2** / **Lesson 3**.
4. Если Д.З. ещё нет — бот покажет «Домашнее задание пока не добавлено» и
   inline-кнопку **➕ Добавить Д.З.**. Нажмите её.
5. Пришлите одно или несколько сообщений любого типа (текст, фото, видео,
   документ, ссылка) — каждое подтвердится строкой «Добавлено в черновик (N)»
   с кнопками **✅ Сохранить** / **❌ Отмена**.
6. Нажмите **✅ Сохранить** — текстовая часть уйдёт в текст урока, остальные
   сообщения сохранятся как вложения и будут пересылаться ученикам/учителю без
   повторной загрузки файлов (`copy_message`).
7. Чтобы изменить уже заполненный урок — откройте его и нажмите
   **✏️ Изменить Д.З.**: старые вложения удалятся и заменятся новыми при сохранении.

Нажатие кнопки «Назад» посреди сбора черновика трактуется как отмена (решение
принято самостоятельно, т.к. в ТЗ этот случай явно не описан).

## 6. Как проверить Writing/Speaking

С обеими кнопками бот сначала уточняет **уровень** и только потом просит саму работу —
это управляет тем, как именно ИИ оценивает её (см. `modules/ai_feedback.py`):

1. Нажмите **Writing** или **Speaking**.
2. Выберите один из 6 уровней: **Beginner (A1)**, **Elementary (A2)**,
   **Pre-Intermediate (B1)**, **Intermediate (B1+)**, **IELTS Novice (B1+/B2)**,
   **IELTS (B2/C1)**. Названия — те же на всех языках интерфейса (как и уровни
   учебника в главном меню, но это **отдельный** список именно для ИИ-фидбека).
3. Только для двух IELTS-уровней бот дополнительно спросит: для Writing —
   **Task 1 (Report)** или **Task 2 (Essay)** (Task 1 — Academic, см. раздел 10);
   для Speaking — **Part 1**, **Part 2** или **Part 3**.
4. Бот попросит прислать **вопрос/задание**, на которое вы отвечали — этот шаг
   обязателен для всех уровней (без него ИИ не может оценить, раскрыта ли тема) и
   принимает **текст, фото, PDF или .docx**. Для IELTS Academic Task 1 задание почти
   всегда визуальное (график/диаграмма/таблица) — пришлите его фото или PDF, и модель
   реально «посмотрит» на него при оценке отчёта, а не будет судить текст в отрыве от
   данных. Многостраничный PDF конвертируется постранично (до 3 страниц); из `.docx`
   вынимается текст. Старый бинарный `.doc` не поддерживается (см. раздел 10).
5. Наконец бот просит саму работу: для Writing — текст сочинения или его фото; для
   Speaking — голосовое/видео-сообщение (Speaking дополнительно расшифровывается через
   Whisper, `OPENAI_TRANSCRIBE_MODEL`, прежде чем передаётся на проверку).
6. ИИ (`OPENAI_MODEL`) отвечает по фиксированной структуре — «Burger technique»
   (короткая похвала → развёрнутый разбор по существу → короткая мотивация, каждое
   конкретное исправление — парой ❌/✅, в конце список полезной лексики по теме), с
   калибровкой под выбранный уровень (без терминов IELTS для уровней 1–4; с баллами по
   официальным критериям для IELTS-уровней). Полный текст системных промптов,
   присланных заказчиком дословно, — в `modules/ai_feedback.py`
   (`WRITING_SYSTEM_PROMPT`/`SPEAKING_SYSTEM_PROMPT`).
7. Фидбек приходит **файлом `.docx`** (не стеной текста в чате) — сначала на английском,
   затем на языке интерфейса ученика (для английского интерфейса — только один раз);
   цитаты ученика и термины IELTS (Band, Task Achievement и т.п.) остаются на
   английском в обеих копиях.
8. После получения фидбека бот **не завершает диалог**, а сразу предлагает прислать
   следующий ответ на **тот же** вопрос/уровень/задание — удобно, когда учитель проверяет
   Writing/Speaking сразу нескольких учеников по одному общему заданию, не выбирая
   уровень и не пересылая вопрос заново для каждого. Нажмите **«Назад»**, чтобы
   закончить и вернуться в главное меню.

На любом из шагов (кроме уже описанного повтора в п. 8) кнопка «Назад» отменяет весь
процесс целиком и возвращает в главное меню — так же, как и везде в этом боте.

## 7. Доступ: «Кто вы?» → подтверждение админом

`TEACHER_IDS` из `.env` остаются **бутстрап-админами** — они получают полный доступ
сразу, без запроса, как и раньше (`role='teacher'`, без очереди подтверждения). Любой
другой пользователь при первом `/start`, сразу после выбора языка, сам указывает,
кто он:

```
Кто вы?
[ 🎓 Я ученик ]   [ 🧑‍🏫 Я учитель ]
```

Это лишь **заявка** — она уходит `access_status='pending'`, и **каждому** админу из
`TEACHER_IDS` приходит уведомление с именем, Telegram ID и заявленной ролью:

```
🔔 Новый запрос на доступ.
Имя: Иван Петров
Telegram ID: 123456789
Роль: Учитель

Выдать доступ?
[ ✅ Разрешить ]  [ ❌ Отклонить ]
```

- **✅ Разрешить**, заявка «Ученик» → тот же результат, что и раньше: **просмотр**
  дерева Level→Unit→Lesson (без «Добавить/Изменить Д.З.») + Writing/Speaking,
  работы сохраняются под его `user_id`.
- **✅ Разрешить**, заявка «Учитель» → **полный** доступ, как у бутстрап-админа:
  Add/Edit Д.З. по любому уроку, тот же уровень прав, что и у `TEACHER_IDS` — но
  без правки `.env` и перезапуска бота. ⚠️ **Это реальное повышение привилегий** —
  один неверный тап «Разрешить» даёт постороннему полный доступ к контенту курса;
  админу стоит проверять имя/ID, прежде чем подтверждать заявку «Учитель».
- **❌ Отклонить** → доступа нет, независимо от заявленной роли.
- Если несколько админов в `TEACHER_IDS` — решает тот, кто нажмёт первым; остальные
  при попытке нажать свою копию уведомления увидят «Этот запрос уже обработан».
- Роль, выданная админом, **не сбрасывается** при следующих `/start` (в отличие от
  бутстрап-админов, чья роль всегда пересчитывается из `TEACHER_IDS`) — см.
  `database/db.py::upsert_user`, параметр `force_role`.
- Повторной подачи заявки после отказа в этой версии нет (осознанное упрощение —
  не описано в исходном задании).

**Решение по интерпретации ТЗ**: раздел 1 исходного ТЗ говорит, что ученик получает
«то же дерево навигации... в режиме только просмотра» — без ограничения по уровню.
Более поздняя строка в разделе 5.3 неоднозначно упоминает «только его собственный»
уровень, но нигде в ТЗ нет механизма назначить ученику конкретный уровень — поэтому
реализован **полный доступ на просмотр** ко всем 4 уровням, а не к одному.

## 10. Известные ограничения и отклонения от ТЗ этой версии

- **IELTS Writing (Task 1 и Task 2) — отдельный жёсткий формат вывода, не Burger-проза.**
  Заказчик прислал 2 готовых образца детального разбора (постраничный/попредложенческий,
  с `Estimated Band` по каждому абзацу, консолидированным списком правок, разделом
  «Why It Is Not Band X» и итоговым Sample/Model Essay) и попросил воспроизводить их
  один в один. Реализовано как полная замена Burger-техники — но **только** для двух
  уровней (`ielts_novice`, `ielts`) и только для Writing (Task 1 или Task 2 — структуры
  разные, см. `modules/ai_feedback.py::_IELTS_WRITING_TASK1_STRUCTURE`/
  `_IELTS_WRITING_TASK2_STRUCTURE`). Уровни 1–4 и Speaking (по ним таких образцов не
  присылали) продолжают использовать прежний Burger-прозовый формат без изменений.
  Стиль итогового Sample/Model Essay в конце разбора тоже не придуман, а выведен из
  присланного сборника образцовых работ (`_SAMPLE_ESSAY_STYLE_TASK1`/`_TASK2`).
- **Итоговые баллы по 4 критериям — в начале ответа, до постатейного разбора.**
  По прямой просьбе заказчика структурный шаблон Task 1/Task 2 теперь начинается с
  блока `## Overall Band Scores` (4 критерия + Overall Band, среднее с официальным
  IELTS-округлением до 0.5) — только после него идут пронумерованные секции
  1–7/paragraph-by-paragraph разбор, как раньше.
- **Фидбек по чистым (без ошибок) предложениям — не комментируется вообще.**
  Section 3 («Body Paragraph») шаблона Task 1 раньше требовала хотя бы короткую
  похвалу на каждое предложение («Excellent structure.») — заказчик отметил, что это
  выглядит как «мелочность»/лишний шум. Теперь предложение без реальной ошибки не
  получает ни заголовка `**Sentence N**`, ни какого-либо комментария вообще —
  разбираются только предложения с настоящей грамматической/лексической/фактической
  проблемой. На `gpt-4o-mini` это соблюдалось лишь примерно в половине случаев
  (модель всё равно вставляла короткую фразу вроде «No issues; this sentence is
  accurate» вместо полного пропуска, несмотря на 3 раунда усиления промпта) — тот же
  класс проблемы, что и с ❌/✅-форматом и IELTS-баллами раньше в этой сессии. Решено
  переключением модели, см. пункт про `OPENAI_MODEL` ниже, а не дальнейшим
  раздуванием промпта.
- **Docx-фидбек — реальное форматирование Word, не сырой markdown-текст.**
  `modules/feedback_doc.py` был лёгким построчным парсером, который резал ответ
  модели по пустым строкам и клал как есть — из-за этого в готовом файле были видны
  сырые `##`/`**` символы, что заказчик отметил как «выдаёт, что это ИИ». Теперь это
  настоящий (хоть и лёгкий, не полноценный markdown-движок) конвертер: `###` →
  жирный текст без решёток, `**bold**` → настоящее жирное форматирование без
  звёздочек, `- пункт`/`1. пункт` → реальный маркированный/нумерованный список Word
  (стили `List Bullet`/`List Number`), markdown-таблицы `| a | b |` → настоящая
  таблица Word (`Table Grid`). Межстрочный интервал 1.5 задан на уровне стиля
  `Normal` и на каждом добавляемом абзаце — тоже прямая просьба заказчика.
- **Band-дескрипторы IELTS Writing/Speaking — официальный текст IELTS.org, не
  парафраз.** Заказчик прислал официальные PDF (IELTS Writing Band Descriptors и
  IELTS Speaking Band Descriptors, «Updated May 2023») и попросил оценивать именно
  по ним. Таблицы в `WRITING_SYSTEM_PROMPT`/`SPEAKING_SYSTEM_PROMPT`
  (`modules/ai_feedback.py`) заменены дословным текстом этих документов, полная
  шкала Band 0–9 по каждому критерию (Task Achievement/Task Response — раздельно
  для Task 1 и Task 2, так как официальный текст для них разный; Coherence and
  Cohesion — тоже раздельно по той же причине; Lexical Resource и Grammatical Range
  — общие таблицы, текст в обоих документах идентичен; для Speaking — все 4
  критерия, включая Pronunciation). Область действия не изменилась: только
  `ielts_novice`/`ielts`, уровни 1–4 по-прежнему не видят баллов и терминологии
  IELTS вообще. Pronunciation по-прежнему не оценивается по одному транскрипту без
  аудио — официальная таблица оставлена для справки, но модели прямо запрещено
  придумывать по ней балл (см. `## IMPORTANT LIMITATION` в `SPEAKING_SYSTEM_PROMPT`).
- **ИИ-провайдер — OpenAI, а не Gemini.** Исходное ТЗ (раздел 2) явно требовало
  `google-genai`. У заказчика на момент разработки был доступен только ключ OpenAI,
  поэтому по его прямому решению `modules/ai_feedback.py` реализован на OpenAI SDK
  (`openai>=1.40,<2.0`). Публичные функции модуля (`get_writing_feedback`,
  `get_speaking_feedback`) сохранили ту же сигнатуру, так что `handlers/teacher.py`
  не завязан на конкретного провайдера — при необходимости вернуться на Gemini
  потребуется переписать только этот один файл.
- **Speaking оценивается по транскрипту, а не по сырому аудио.** У Gemini есть
  готовый инлайн-приём audio/video в chat-модель; у используемых chat-моделей
  OpenAI такого нет. Поэтому голосовое/видео сообщение сначала расшифровывается
  Whisper'ом (`OPENAI_TRANSCRIBE_MODEL`, по умолчанию `whisper-1` — принимает
  форматы Telegram voice (`ogg`) и video (`mp4`) напрямую, без конвертации), а
  затем текст транскрипта проверяется на грамматику/лексику/беглость. Акустическое
  произношение (интонация, чистота звуков) в этой версии не оценивается — бот
  явно предупреждает об этом в самом фидбеке.
- **Материалы (Level→Unit→Lesson) — только для учителя, ученик их больше не
  видит вообще.** Раньше одобренный ученик тоже мог их просматривать в
  read-only режиме (`editable=False`); заказчик прямо попросил убрать это —
  теперь главное меню одобренного не-учителя (`content_tree.build_student_
  menu_keyboard`) состоит ровно из 2 кнопок, Writing и Speaking. Это не только
  косметика: `handlers/teacher.py::handle_navigation_text` тоже блокирует
  саму навигацию для не-учителя (не только прячет кнопки), так что случайный
  текст или зависшая старая клавиатура не открывают доступ к материалам —
  студент получает `error_materials_teacher_only`. Нет UI для отзыва уже
  выданного доступа или повторной подачи заявки после отказа — оба сценария не
  описаны в ТЗ, при необходимости решаются напрямую через `sqlite3 bot.db`
  (`UPDATE users SET access_status = ...`).
- **`OPENAI_MODEL` переключён с `gpt-4o-mini` на `gpt-5.4-mini`.** На всём
  протяжении этой сессии `gpt-4o-mini` регулярно нарушал строгие требования
  формата — пропускал IELTS band-числа, давал ❌/✅-пары нестабильно (~50%),
  иногда откатывался с жёсткого Task1/Task2 шаблона на исходную Burger-прозу,
  не пропускал предложения без ошибок как просили и один раз выдал Overall
  Band не кратный 0.5 (5.8 вместо 5.75→6.0). Живое сравнение показало, что
  `gpt-5.4-mini` (та же ценовая категория — «mini») заметно надёжнее следует
  этим же длинным составным инструкциям без единой правки в самом промпте:
  повторный прогон тех же тестов дал 4/4 по строгому формату, 0/4 по
  «лишним» комментариям и корректное 0.5-округление баллов на каждом запуске.
- **Системные промпты Writing/Speaking — от заказчика, встроены дословно.**
  `modules/ai_feedback.py::WRITING_SYSTEM_PROMPT`/`SPEAKING_SYSTEM_PROMPT` — это
  присланные заказчиком инструкции без единой правки по содержанию (только собраны
  из мойбейка/markdown в чистый текст). Уровни/баллы/структура ответа калибруются
  самой моделью по этому тексту, а не Python-кодом — код лишь передаёт `student_level`
  (и `task_type`/`test_part` для IELTS-уровней) и `question` в размеченном
  user-сообщении.
- **Writing Task 1 — IELTS Academic, не General Training.** Исходный промпт по
  умолчанию был написан под GT (Task 1 = письмо) и сам отмечал это как допущение;
  по прямому решению заказчика переключено на Academic (Task 1 = отчёт по
  графику/диаграмме/таблице) — см. `WRITING_SYSTEM_PROMPT` в `modules/ai_feedback.py`.
  GT-режим не реализован; вернуть его — значит заменить только этот раздел промпта.
- **Материал задания: PDF/фото — да, старый `.doc` — нет.** `modules/file_intake.py`
  конвертирует PDF-страницы в картинки (PyMuPDF) и достаёт текст из `.docx`
  (python-docx), но не читает старый бинарный `.doc` — библиотека для чтения `.docx`
  его не поддерживает, а тянуть системный конвертер (LibreOffice/antiword) ради
  редкого формата на сервер не стали. Пользователь получает понятную ошибку и может
  пересохранить файл как `.docx` или PDF.
- **Фидбек-файл — `.docx`, не `.pdf`.** `modules/feedback_doc.py` использует
  python-docx: простой, надёжный рендеринг без сторонних системных зависимостей
  (генерация PDF с приличной типографикой потребовала бы либо LibreOffice на
  сервере, либо отдельной вёрстки через reportlab) — .docx открывается везде и
  этого достаточно для читаемого документа.
- **Пакетный режим Writing/Speaking не различает учеников.** Все ответы, присланные
  подряд на один вопрос (раздел 6, п. 8), сохраняются в `submissions` под `user_id`
  того, кто их отправляет (обычно — учитель, пересылающий работы учеников) — выбора
  «за какого ученика» в этой версии нет, интерфейс не про это просили.
- **6 уровней Writing/Speaking не связаны с 4 уровнями Empower.** Beginner (A1) …
  IELTS (B2/C1) — это калибровка ИИ-фидбека (`modules/ai_feedback.py::FEEDBACK_LEVELS`),
  отдельная от уровней учебника в дереве Level→Unit→Lesson; первые 4 названия
  совпадают по смыслу, но это не один и тот же список в коде.
- **Билингвальный вывод фидбека — по решению заказчика**, а не по ТЗ: исходные
  промпты вообще не оговаривают язык ответа (только английский), а исходное ТЗ
  требовало отвечать на языке интерфейса. Решение: сначала полный ответ на
  английском, затем (если язык интерфейса не английский) тот же ответ на языке
  ученика — см. `_bilingual_suffix()` в `modules/ai_feedback.py`.
- `JobQueue`, расписания и напоминания не реализованы — не требуются по ТЗ.
- Один учитель, работающий над черновиком Д.З., хранит его в `context.user_data`
  текущего диалога — черновик не переживает перезапуск процесса бота.
