# English Bot (Empower) — Telegram-бot для учителя английского языка

Telegram-бот для управления домашними заданиями по учебнику **Empower** (4 уровня ×
12 юнитов × 3 урока) и для проверки ученических работ **Writing/Speaking** с помощью
ИИ (OpenAI). Управление — через кнопочное меню (reply-keyboard), без слэш-команд.

> **Отклонение от исходного ТЗ**: изначально был указан google-genai/Gemini, но у
> заказчика был готов ключ только от OpenAI — по его решению провайдер заменён на
> OpenAI (`modules/ai_feedback.py`). Подробности — в разделе 9.

Учитель полностью управляет контентом (навигация Level→Unit→Lesson, добавление Д.З.).
Любой другой пользователь ("ученик") может получить **доступ на просмотр** того же
дерева уроков и пользоваться Writing/Speaking — но только после того, как учитель
одобрит его запрос прямо в Telegram (раздел 7).

## 1. Технологии

- Python 3.11+
- python-telegram-bot v22.x (асинхронный API)
- openai (официальный Python SDK OpenAI, `from openai import OpenAI`)
- sqlite3 (встроенный модуль)
- python-dotenv

## 2. Установка и запуск

```bash
cd english_bot
python -m venv .venv
# Windows:
.venv\Scripts\activate
# Linux/macOS:
source .venv/bin/activate

pip install -r requirements.txt
cp .env.example .env   # затем заполнить .env, см. ниже
python bot.py
```

При первом запуске бот автоматически создаст файл БД (`bot.db`) со всеми таблицами
и заранее засеет 144 пустых урока (4 уровня × 12 юнитов × 3 урока).

## 3. Заполнение `.env`

### 3.1 BOT_TOKEN
1. Откройте Telegram, найдите **@BotFather**.
2. Отправьте `/newbot` и следуйте инструкциям (укажите имя и username бота).
3. BotFather пришлёт токен вида `123456789:AAExxxxxxxxxxxxxxxxxxxxxxxxxxxxxxx` —
   вставьте его в `BOT_TOKEN`.

### 3.2 OPENAI_API_KEY
1. Перейдите на https://platform.openai.com/api-keys.
2. Войдите в аккаунт OpenAI и создайте новый ключ (Create new secret key).
3. Вставьте его в `OPENAI_API_KEY`. Ключ должен начинаться с `sk-...`, и на счету
   должен быть баланс/привязан способ оплаты — иначе запросы будут падать с
   ошибкой квоты (бот в этом случае покажет пользователю понятное сообщение об
   ошибке, см. ключ `error_ai_provider` в `locales.py`).

### 3.3 Свой Telegram ID (для TEACHER_IDS)
1. Откройте Telegram, найдите **@userinfobot**.
2. Отправьте ему любое сообщение — бот пришлёт в ответ ваш числовой ID.
3. Впишите его в `TEACHER_IDS` (через запятую, если учителей несколько:
   `TEACHER_IDS=111111111,222222222`).

### 3.4 Остальное
- `OPENAI_MODEL` — chat-модель для Writing и разбора Speaking-транскрипта (по
  умолчанию `gpt-4o-mini` — дешёвая и достаточно качественная для этой задачи,
  можно сменить без изменения кода).
- `OPENAI_TRANSCRIBE_MODEL` — модель распознавания речи (по умолчанию `whisper-1`).
- `DATABASE_PATH` — путь к файлу SQLite (по умолчанию `bot.db`).
- `MAX_MEDIA_SIZE_MB` — лимит размера аудио/видео для Speaking (по умолчанию 20 МБ).

## 4. Как выглядит выбор языка

Сразу после `/start` бот показывает inline-кнопки:

```
🌐 Выберите язык интерфейса / Tilni tanlang / Choose language:
[ 🇺🇿 O'zbekcha ]  [ 🇷🇺 Русский ]  [ 🇬🇧 English ]
```

Выбор сохраняется в БД (`users.language`) и используется во всех дальнейших
сообщениях этому пользователю: меню, кнопки, подсказки, ошибки, фидбек по
Writing/Speaking. Изменить язык повторно в этой версии нельзя — он запрашивается
только один раз, при первом `/start`.

После выбора языка учитель видит главное меню (2 столбца):

```
Beginner          Elementary
Pre-Intermediate  Intermediate
Writing           Speaking
```

## 5. Как добавить домашнее задание к уроку

1. В главном меню выберите уровень (например, **Beginner**).
2. Выберите юнит: **Unit 1** … **Unit 12**.
3. Выберите урок: **Lesson 1** / **Lesson 2** / **Lesson 3**.
4. Если Д.З. ещё нет — бот покажет «Домашнее задание пока не добавлено» и
   inline-кнопку **➕ Добавить Д.З.**. Нажмите её.
5. Пришлите одно или несколько сообщений любого типа (текст, фото, видео,
   документ, ссылка) — каждое подтвердится строкой «Добавлено в черновик (N)»
   с кнопками **✅ Сохранить** / **❌ Отмена**.
6. Нажмите **✅ Сохранить** — текстовая часть уйдёт в текст урока, остальные
   сообщения сохранятся как вложения и будут пересылаться ученикам/учителю без
   повторной загрузки файлов (`copy_message`).
7. Чтобы изменить уже заполненный урок — откройте его и нажмите
   **✏️ Изменить Д.З.**: старые вложения удалятся и заменятся новыми при сохранении.

Нажатие кнопки «Назад» посреди сбора черновика трактуется как отмена (решение
принято самостоятельно, т.к. в ТЗ этот случай явно не описан).

## 6. Как проверить Writing/Speaking

С обеими кнопками бот сначала уточняет **уровень** и только потом просит саму работу —
это управляет тем, как именно ИИ оценивает её (см. `modules/ai_feedback.py`):

1. Нажмите **Writing** или **Speaking**.
2. Выберите один из 6 уровней: **Beginner (A1)**, **Elementary (A2)**,
   **Pre-Intermediate (B1)**, **Intermediate (B1+)**, **IELTS Novice (B1+/B2)**,
   **IELTS (B2/C1)**. Названия — те же на всех языках интерфейса (как и уровни
   учебника в главном меню, но это **отдельный** список именно для ИИ-фидбека).
3. Только для двух IELTS-уровней бот дополнительно спросит: для Writing —
   **Task 1 (Letter)** или **Task 2 (Essay)**; для Speaking — **Part 1**, **Part 2**
   или **Part 3**.
4. Бот попросит прислать **вопрос/задание**, на которое вы отвечали (текстом) — это
   обязательный шаг для всех уровней, без него ИИ не может оценить, раскрыта ли тема.
5. Наконец бот просит саму работу: для Writing — текст сочинения или его фото; для
   Speaking — голосовое/видео-сообщение (Speaking дополнительно расшифровывается через
   Whisper, `OPENAI_TRANSCRIBE_MODEL`, прежде чем передаётся на проверку).
6. ИИ (`OPENAI_MODEL`) отвечает по фиксированной структуре — «Burger technique»
   (похвала → разбор по существу → мотивация), с калибровкой под выбранный уровень
   (без терминов IELTS для уровней 1–4; с баллами по официальным критериям для
   IELTS-уровней). Полный текст системных промптов, присланных заказчиком дословно, —
   в `modules/ai_feedback.py` (`WRITING_SYSTEM_PROMPT`/`SPEAKING_SYSTEM_PROMPT`).
7. Фидбек приходит **сначала на английском, затем на языке интерфейса ученика**
   (для английского интерфейса — только один раз); цитаты ученика и термины IELTS
   (Band, Task Achievement и т.п.) остаются на английском в обеих копиях.

На любом из шагов кнопка «Назад» отменяет весь процесс целиком и возвращает в главное
меню (не на шаг назад) — так же, как и везде в этом боте.

## 7. Доступ для учеников (запрос → подтверждение учителем)

Любой пользователь, который не входит в `TEACHER_IDS`, после выбора языка получает
`role='student'` и `access_status='pending'`, видит сообщение «Ваш запрос на доступ
отправлен учителю...», а **каждому** учителю из `TEACHER_IDS` приходит уведомление:

```
🔔 Новый запрос на доступ.
Имя: Иван Петров
Telegram ID: 123456789

Выдать доступ на просмотр материалов?
[ ✅ Разрешить ]  [ ❌ Отклонить ]
```

- **✅ Разрешить** → ученику приходит «Вам открыт доступ...» и то же главное меню,
  что видит учитель (Beginner/Elementary/Pre-Intermediate/Intermediate/Writing/Speaking).
  Дальше он ходит по **тому же дереву** Level→Unit→Lesson и видит те же материалы
  (текст + пересланные вложения), но **без** кнопок «Добавить/Изменить Д.З.» — режим
  строго «только просмотр». Writing/Speaking работают у него так же, как у учителя,
  только работа сохраняется под его собственным `user_id`.
- **❌ Отклонить** → ученику приходит «Вам не предоставлен доступ...», доступа нет.
- Если несколько учителей в `TEACHER_IDS` — решает тот, кто нажмёт первым; остальные
  при попытке нажать свою копию уведомления увидят «Этот запрос уже обработан».
- Повторной отправки запроса после отказа в этой версии нет (осознанное упрощение —
  в ТЗ этот случай не описан).

**Решение по интерпретации ТЗ**: раздел 1 исходного ТЗ говорит, что ученик получает
«то же дерево навигации... в режиме только просмотра» — без ограничения по уровню.
Более поздняя строка в разделе 5.3 неоднозначно упоминает «только его собственный»
уровень, но нигде в ТЗ нет механизма назначить ученику конкретный уровень — поэтому
реализован **полный доступ на просмотр** ко всем 4 уровням, а не к одному.

## 10. Известные ограничения и отклонения от ТЗ этой версии

- **ИИ-провайдер — OpenAI, а не Gemini.** Исходное ТЗ (раздел 2) явно требовало
  `google-genai`. У заказчика на момент разработки был доступен только ключ OpenAI,
  поэтому по его прямому решению `modules/ai_feedback.py` реализован на OpenAI SDK
  (`openai>=1.40,<2.0`). Публичные функции модуля (`get_writing_feedback`,
  `get_speaking_feedback`) сохранили ту же сигнатуру, так что `handlers/teacher.py`
  не завязан на конкретного провайдера — при необходимости вернуться на Gemini
  потребуется переписать только этот один файл.
- **Speaking оценивается по транскрипту, а не по сырому аудио.** У Gemini есть
  готовый инлайн-приём audio/video в chat-модель; у используемых chat-моделей
  OpenAI такого нет. Поэтому голосовое/видео сообщение сначала расшифровывается
  Whisper'ом (`OPENAI_TRANSCRIBE_MODEL`, по умолчанию `whisper-1` — принимает
  форматы Telegram voice (`ogg`) и video (`mp4`) напрямую, без конвертации), а
  затем текст транскрипта проверяется на грамматику/лексику/беглость. Акустическое
  произношение (интонация, чистота звуков) в этой версии не оценивается — бот
  явно предупреждает об этом в самом фидбеке.
- Доступ ученика — только на просмотр (без Add/Edit HW); нет UI для отзыва уже
  выданного доступа или повторной подачи заявки после отказа — оба сценария не
  описаны в ТЗ, при необходимости решаются напрямую через `sqlite3 bot.db`
  (`UPDATE users SET access_status = ...`).
- **Системные промпты Writing/Speaking — от заказчика, встроены дословно.**
  `modules/ai_feedback.py::WRITING_SYSTEM_PROMPT`/`SPEAKING_SYSTEM_PROMPT` — это
  присланные заказчиком инструкции без единой правки по содержанию (только собраны
  из мойбейка/markdown в чистый текст). Уровни/баллы/структура ответа калибруются
  самой моделью по этому тексту, а не Python-кодом — код лишь передаёт `student_level`
  (и `task_type`/`test_part` для IELTS-уровней) и `question` в размеченном
  user-сообщении.
- **Writing по умолчанию — General Training, не Academic.** Так исходный промпт
  прямо обозначил как допущение (Task 1 = письмо, а не описание графика/диаграммы);
  Academic Task 1 не реализован.
- **6 уровней Writing/Speaking не связаны с 4 уровнями Empower.** Beginner (A1) …
  IELTS (B2/C1) — это калибровка ИИ-фидбека (`modules/ai_feedback.py::FEEDBACK_LEVELS`),
  отдельная от уровней учебника в дереве Level→Unit→Lesson; первые 4 названия
  совпадают по смыслу, но это не один и тот же список в коде.
- **Билингвальный вывод фидбека — по решению заказчика**, а не по ТЗ: исходные
  промпты вообще не оговаривают язык ответа (только английский), а исходное ТЗ
  требовало отвечать на языке интерфейса. Решение: сначала полный ответ на
  английском, затем (если язык интерфейса не английский) тот же ответ на языке
  ученика — см. `_bilingual_suffix()` в `modules/ai_feedback.py`.
- `JobQueue`, расписания и напоминания не реализованы — не требуются по ТЗ.
- Один учитель, работающий над черновиком Д.З., хранит его в `context.user_data`
  текущего диалога — черновик не переживает перезапуск процесса бота.
